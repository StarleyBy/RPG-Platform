# RPG Manifest — синк с Google Таблицами

Google Apps Script проект: массовое наполнение манифестов через таблицу
вместо формы «один предмет за раз». Схемы (`data/schemas/*.json`) и
словари (`data/vocab/*.json`) остаются единственным источником правды —
этот инструмент их не дублирует, а читает и на их основе строит структуру
листов (заголовки, выпадающие списки).

## ⚠️ Честно про тестирование

У меня не было доступа к живому Google Apps Script/Sheets/Drive, поэтому
я не смог прогнать это так же, как HTML-редактор (там — сквозные тесты
через jsdom на реальном браузерном движке). Что я **реально** проверил:

- **Вся логика без обращений к Google API** (`RuDict.gs`, `TokenResolver.gs`,
  `AbilityListCodec.gs`, `SheetLayout.gs`, и функция `_buildObjectFromRow_`
  из `Exporter.gs`) — прогнана через Node.js на юнит-тестах: перевод
  RU↔EN, разбор мини-синтаксиса способностей, сборка строки таблицы в
  JSON-манифест точно той структуры, что ждут Godot и HTML-редактор. Один
  реальный баг нашёл и исправил в процессе (сравнение "6 — Эпическое" с
  просто "Эпическое" не срабатывало — добавил допуск на числовой префикс).
- **Синтаксис всех `.gs`-файлов** — валиден как JS (Apps Script — это V8,
  проверено через `node --check`), нет дублирующихся объявлений функций.

Что я **не** смог проверить: реальные вызовы `SpreadsheetApp`, `DriveApp`,
`UrlFetchApp`, `PropertiesService`, установку триггеров, диалоговое окно
настроек в реальном UI Google Sheets. Код написан по документации этих
API, но перед тем как доверять ему реальные данные — **обязательно
пройди smoke-тест ниже на 2-3 тестовых строках**.

## Установка

1. Создай новую Google Таблицу.
2. Расширения → Apps Script.
3. Удали содержимое стандартного `Code.gs`.
4. Создай в проекте файлы с точно такими же именами, как в этой папке, и
   скопируй содержимое каждого: `RuDict.gs`, `Config.gs`, `SchemaLoader.gs`,
   `TokenResolver.gs`, `AbilityListCodec.gs`, `SheetLayout.gs`,
   `IdValidator.gs`, `SheetBuilder.gs`, `Exporter.gs`, `Menu.gs`.
   Для `SettingsDialog.html` — в Apps Script жми "+" → HTML, назови файл
   `SettingsDialog` (без расширения, Apps Script сам добавит `.html`).
5. В настройках проекта (значок шестерёнки слева) вставь содержимое
   `appsscript.json` вместо стандартного манифеста (там прописаны нужные
   права доступа — Sheets, Drive, внешние запросы).
6. Сохрани всё, вернись в таблицу и обнови страницу браузера — сверху
   появится меню **🎮 RPG Manifest**.

Если пользуешься `clasp` (CLI для Apps Script) — просто `clasp push` из
этой папки, она уже в формате clasp-проекта.

## Настройка источника данных

1. Загрузи папки `data/schemas/` и `data/vocab/` (из основного архива
   проекта) на Google Диск как есть — по одному файлу на схему/словарь.
2. Создай ещё одну пустую папку на Диске — сюда будут писаться
   `game_data/**` при экспорте.
3. Скопируй ID всех трёх папок из ссылок (`drive.google.com/drive/folders/ЭТА_ЧАСТЬ`).
4. В таблице: 🎮 RPG Manifest → ⚙️ Настройки источника данных → режим
   "📁 Google Диск" → вставь три ID → Сохранить.

(Режим "🐙 GitHub" будет иметь смысл только когда репозиторий станет
публичным или ты дашь скрипту доступ иначе — на момент этой сессии
`github.com/StarleyBy/RPG_Platform_Core` возвращал 404.)

## Обязательный smoke-тест перед реальной работой

1. 🎮 RPG Manifest → 🔄 Обновить структуру листов из схем.
   Должно создаться 32 вкладки (по одной на схему), плюс служебный лист
   `_Списки`. Открой вкладку "⚔️ Оружие" — проверь, что колонка "Подтип"
   при клике показывает выпадающий список на русском (Меч, Топор...).
2. Впиши в первую строку данных: ID = `test_sword_01`, Название =
   `Тестовый меч`, Подтип = выбери "Меч" из списка, Редкость = "3 —
   Обычное", отметь галочкой "✅ Урон оружия", впиши в "Физический"
   `10-20`.
3. 🎮 RPG Manifest → ✅ Проверить дубликаты ID — должно сказать "конфликтов
   не найдено".
4. 🎮 RPG Manifest → 📤 Экспортировать всё в Google Диск.
5. Проверь папку вывода на Диске: должен появиться путь
   `game_data/items/weapon/test_sword_01.json` с корректным содержимым
   (`"subtype": "sword"`, `"rarity": "3_common"`, `"weapon_damage":
   {"enabled": true, "physical": [10, 20], ...}`).
6. Введи ещё один ID `test_sword_01` на любом другом листе (например,
   "🌿 Материалы...") — 🔔 живая проверка (после "Включить живую проверку
   ID") должна подсветить обе ячейки красным с пояснением, где конфликт;
   при попытке экспорта — жёсткая остановка без записи файлов.

Если всё это подтвердилось — можно наполнять реальными данными.

## Мини-синтаксис для "Список способностей" (ability_list)

Одна ячейка = список эффектов через `;`, поля внутри одного эффекта — `:`:

```
глагол:цель:область:модификатор:значение:условие[:формула[:заметка]]
```

Можно писать сегменты по-русски или по-английски вперемешку — резолвер
понимает оба варианта, а нераспознанное слово просто остаётся как
"свой вариант" (то же самое поведение `allow_custom`, что в HTML-редакторе).

Примеры:
```
увеличивает:crit_chance:на себя:в процентах:10:при крите
grants:fire_damage:self:flat:5-9:on_hit::ключевой ингредиент
increases:physical_damage:self:formula:::0.001 * PLAYER_LEVEL
```

## Что решает эту таблицу, а что — нет

Хорошо подходит для: материалов, рядового оружия/брони по вариантам,
зелий по тирам, рядовых существ по региону, ресурсов, еды — массового
систематического контента, где десятки похожих строк.

**Не заменяет HTML-редактор** для штучных, авторских вещей (уникальные
артефакты, боссы, именные локации) — там живая подсказка по формуле,
проверка ID в реальном времени и явное поле "свой вариант" всё ещё удобнее
делать через форму, а не через одну ячейку таблицы.

## Известные ограничения

- Недеструктивное обновление структуры листа матчит колонки по ключу
  (Note на ячейке шапки), а не по позиции — но если кто-то вручную сотрёт
  Note у заголовка, колонка "потеряется" для скрипта (данные не пропадут,
  но перестанут экспортироваться, пока не пересоздать колонку).
- Перезапись файла на Диске реализована как "переместить старую версию в
  корзину + создать новую" (Apps Script базового DriveApp не даёт
  überwrite-in-place без Advanced Drive Service) — то есть при повторном
  экспорте в корзине будет накапливаться история версий. Можно почистить
  корзину вручную или добавить очистку в `_writeOrOverwriteFile_`.
- Импорт существующих JSON обратно в таблицу (обратное направление) не
  реализован — `serializeAbilityList()` для этого готов, но полного
  "заполнить строки из game_data/**" скрипта нет. Скажи, если это нужно —
  это отдельная, но не очень большая задача поверх уже готового кода.
